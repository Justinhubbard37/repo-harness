- `LedgerEnforcement` checks `tasks/lessons.md` in each PR against the Lessons Retro contract: every non-blank line belongs to a parsed entry, the required and known fields, the `Missed by` values, a cumulative `Seen` for each theme, a resolving `Enforced by` path or rule id, `Promoted` at `Seen` 3× or more with `Enforced by: judgment`, and every `Triggered by correction` reference of the merge-base. `Mistake pattern` is the immutable theme key (lowercase words joined by `-`), and a head theme continues only the merge-base theme with the same key: a key that leaves the ledger fails, a theme maximum never falls, a consolidation keeps the maximum, every `Promoted` reference (a consolidated entry lists them, separated by `, `) and the current `Enforced by`, and a `Name` change is free. A field line is exactly `- <Field>: <value>`, and a continuation line is indented prose without a list marker; any other line in the ledger is a finding. Each finding names the entry, the field and the fix. An existing `Enforced by` reference stops at human review. A theme state that the merge-base already has is reported as carried and does not fail. `scripts/check-ci.sh ledger --base <ref>` runs it; the new `LedgerEnforcement` CI job runs on each PR, documentation-only PRs included, and its failure fails `Required / CI`. `scripts/maintenance-triage.sh --entries <file>` prints the parsed entries with the lines that each entry owns, so the ledger keeps one parser; a repeated field in one entry now keeps its first value, and the `--json` judgment themes group by the exact key and drop the `key` field (use `theme`).
